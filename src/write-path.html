How a governed change worksNo client writes to a plant or business system directly

01 · REQUESTED

Write request

A person or an AI agent asks. It records who asked, the decision behind it, and how to undo it.

02 · APPROVED

Authority

The site's limits decide who approves. Agents never approve, and nobody approves their own request.

03 · APPLIED

Conditional write

Only if the target has not changed since the request. Setpoints must stay inside hard limits.

04 · VERIFIED

Read back

The result is read back and checked. Every step is a hash-chained record an auditor can replay.

Rejected

No decision right, outside the limits, or the target moved. Nothing is written.

Rolled back

The read-back did not match, so the prior value is restored automatically.

Outcome checked later

A falsification condition on the decision lets a verifier report whether the change did what it claimed.
